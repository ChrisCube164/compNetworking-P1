01 // Why This Project

An API needs more than a listening socket

Model inference costs time and computing capacity. If every request goes straight to the model, one busy caller can crowd out everyone else. Real systems place a gateway in front of valuable services to identify callers, enforce policy, and reject excess traffic.

P1 turns that idea into a focused networking problem. The supporting services are local and deliberately small, but your gateway must still frame messages, cross process boundaries, overlap independent waits, and remain correct under concurrent load.

Time finishes first. WHOIS and Redis then run together. The fLLM is contacted only when the request is allowed.

allow = attemptNumber <= limit(tier) DEFAULT or unknown caller: 3  //  REGISTERED caller: 10
Why the Redis result matters: one atomic increment gives each concurrent request a distinct attempt number. The requests may finish in any order, but no more than the caller's limit can be approved.

03 // Meet the Services

Familiar systems, simplified for one purpose

The backend programs are supplied. You connect to them using their wire protocols and combine their answers.

37

RFC 868 Time

Network time services give systems a shared clock; modern networks generally use NTP.

Here: four bytes place each request into a shared 60-second window.

43

WHOIS Registry

WHOIS publishes registration records for Internet resources such as domains and address blocks.

Here: a small registry tells the gateway whether a caller has default or registered access.

R

Redis RESP

Redis is an in-memory data store commonly used for caching, counters, coordination, and rate limiting.

Here: atomic INCR assigns every attempt a unique number.

AI

Local fLLM

Language-model APIs turn prompts into generated responses and are often expensive, shared resources.

Here: a local ELIZA-style service gives the gateway something valuable to protect.

04 // One Request's Journey

Receive, gather, decide, respond

  1. Receive

    Parse one plain-text HTTP request and identify its caller.

    GATEWAY AS SERVER

  2. Gather

    Get the Time window, then query WHOIS and Redis concurrently.

    GATEWAY AS CLIENT

  3. Decide

    Compare the atomic attempt number with the limit for the caller's tier.

    SHARED STATE, SAFE DECISION

  4. Respond

    Forward an allowed query to the fLLM or refuse it with HTTP 429, then answer the original client.

05 // Your Work

Complete the networking core, not the infrastructure

The starter is one Java 21 source file. Its listener, virtual-thread executors, configuration, data types, and fLLM adapter are already present. You implement seven focused methods that make the gateway communicate and decide correctly.

You implement

  • Inbound HTTP request and response framing
  • Small clients for Time, WHOIS, and Redis
  • The concurrent metering and admission decision
  • Cleanup and failure behavior at network boundaries

The project provides

  • The server listener and per-client virtual threads
  • The Time, WHOIS, Redis, and fLLM servers
  • The FakeLLMClient helper
  • Configuration, records, and defensive helpers
  • A local launcher and controlled test environment
The full implementation contract lives in PROMPT.md. Use it for exact wire formats, validation rules, response statuses, development order, and reference links. This page is the map; the Markdown prompt is the field guide.

06 // Start Building

Make several conversations look like one reliable service

A client should not need to know that four backend services participated. It sends one request and receives one answer. Your gateway owns everything in between: message boundaries, protocol translation, concurrent waits, and the final decision.
